# ERC-7730 clear-signing preparation

ERC-7730 is wallet-consumed JSON metadata for displaying EIP-712 messages. It does not add an on-chain interface or replace the protocol's EIP-712 / ERC-1271 verification. This document maps AsyncSwap's signed actions to the metadata we need to publish for compatible wallets.

## Signed actions

| Action | EIP-712 domain | Primary message | User-facing fields |
| --- | --- | --- | --- |
| Create order | Permit2 | `PermitWitnessTransferFrom` with `AsyncOrder` witness | Maker, input token, output token, input amount, minimum output, pool currencies/fee/tick spacing/hook |
| Authorize Router | `AsyncSwap`, version `1` | `SetExecutor` | Maker, executor, allow/deny, pool, nonce, deadline |
| Reprice order | `AsyncSwap`, version `1` | `UpdatePrice` | Maker, input token, output token, input amount, new minimum output, order ID, nonce, deadline |
| Cancel order | `AsyncSwap Router`, version `1` | `CancelOrder` | Maker, input token, output token, input amount, order ID, deadline |

The Solidity type definitions are maintained in `src/libraries/OrderSignatures.sol`. The Permit2 create-order signature also contains the Permit2 transfer permission; the descriptor must preserve that authorization amount and token in the displayed message.

## Descriptor release requirements

Before publishing an ERC-7730 descriptor:

1. Choose the ERC-7730 schema version supported by the target wallet integrations. The ERC-7730 proposal is still Draft, so schema compatibility must be checked at release time.
2. Add exact `chainId` and verifying-contract addresses for the deployed hook and Router. For create-order signing, bind to the canonical Permit2 address on each supported chain.
3. Bind each message to the correct EIP-712 domain (`name`, `version`, `chainId`, and `verifyingContract`) and the exact primary type/dependencies.
4. Format token amounts using the decimals and symbol of the referenced token; preserve raw values and addresses so the wallet can verify what it displays.
5. Validate each descriptor against the selected schema and exercise it in every wallet we claim to support. A descriptor alone does not make an unsupported wallet render clear-signing metadata.

Do not publish a descriptor with placeholder addresses or broad domain matching. The current deployment registry may refer to older bytecode; use the final addresses for the release being described.

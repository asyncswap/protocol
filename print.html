AsyncSwap Protocol

AsyncSwap is a peer-to-peer order protocol built as a Uniswap v4 hook. A maker posts a full-fill order; a filler can settle it when the maker's limit is met. The maker signs the order terms and submits the transaction from their wallet. There is no relayer requirement.

Contract rules

  • Full fills only. Partial fills are planned for a future version.
  • USDC numeraire. Every pool using an AsyncSwap hook must pair one asset with that deployment's configured USDC. This rule applies to anyone initializing a pool with the hook; unrelated v4 pools are unaffected.
  • 0.2% protocol fee. The fee is taken from gross output on successful fills. The maker's signed minimum is net of the fee; creation and cancellation have no protocol fee.
  • Signed actions. EIP-712 signatures support create, authorize, reprice, and cancel actions. ERC-1271 wallets are supported. ERC-20 input uses Permit2; native ETH input requires a transaction.

Contracts

  • src/AsyncSwap.sol — v4 hook, order state, numeraire check, and fee accounting.
  • src/Router.sol — maker and filler entry points.
  • src/libraries/AsyncFiller.sol — order storage and full-fill, reprice, and cancel logic.

Build and test

forge soldeer install
forge build
forge test
forge fmt --check

Deployment

The checked deployment flow currently targets Unichain mainnet only. The existing addresses in deployments/130/130.json may refer to an earlier version; the current source changes require a new hook and Router deployment, followed by initialization of new pools. Existing pools and open orders remain on their current hook.

  • Deployment runbook — inputs, preflight, broadcast, and pool initialization.
  • Chain configuration — configured networks and readiness.
  • Signed-message metadata — wallet display metadata and release checks.
  • USDC numeraire spec — scope and rationale.

Do not enable the new deployment in the frontend or publish wallet metadata until the deployed addresses, supported chains, and security review are final.

AsyncFiller

Git Source

Title: AsyncFiller

Author: @msakiart

Stores open async orders and settles fills against them.

Authorization model: the maker authorizes a Router/executor at order-creation time (setExecutor[owner][executor] = true). All subsequent fill / cancel / updatePrice calls on the hook must come from that registered executor. The hook forwards its immediate caller (msg.sender) and the resolved end-actor address (filler / canceller) into this library; the executor is checked here, and PM settlement targets the actor.

fill

Full-fill. The caller (the hook contract) must be an authorized executor of the order owner; filler is the actual end-user paying the output and receiving the input. Must be invoked from inside an IPoolManager.unlock context.

AsyncOrder

Git Source

Represents an async order for a swap in the Uniswap V4 pool.

struct AsyncOrder {
PoolKey key;
address owner;
bool zeroForOne;
uint256 amountIn;
uint256 amountOutMin;
uint160 sqrtPrice;
bytes32 salt;
}

Properties

NameTypeDescription
keyPoolKeyThe Uniswap V4 PoolKey identifying the pool the order is placed against.
owneraddressThe maker who supplied amountIn of the input currency at order submission.
zeroForOneboolDirection of the order. true => input is currency0, output is currency1.
amountInuint256Amount of input currency the maker is offering. v1 is exact-input, full-fill only.
amountOutMinuint256Minimum amount of output currency the maker accepts. The implicit limit price is amountOutMin / amountIn. A filler MUST deliver at least this much output to claim the maker's input.
sqrtPriceuint160Pool sqrt-price the maker is willing to settle at if they cancel into a regular Uniswap swap. Used as the limit for the cancel-into-swap fallback.
saltbytes32Contract-assigned salt that disambiguates orders. The hook computes this at create time from keccak256(timestamp, block.number, msg.sender, owner, amountIn, amountOutMin) and emits it in AsyncOrderCreated so the maker can reference the order in cancel / updatePrice. Submitters pass bytes32(0) on create — the value in this slot is only read on cancel / updatePrice / fill paths.

AsyncSwap

Git Source

Inherits: BaseHook, EIP712

Title: AsyncSwap

Author: @msakiart

Uniswap v4 hook that converts an exact-input swap into an open async order: the maker deposits their input via _beforeSwap, and a filler later settles by paying the maker's limit-priced output. v1 is full-fill only. Makers can also act by EIP-712 signature (setExecutorWithSig, updatePriceWithSig) so a relayer pays gas and the wallet shows a readable message. See OrderSignatures for types.

receive

Accept ETH transfers. The Router (or any caller paying for a native-output fill) forwards msg.value to the hook before triggering executeOrder. The hook records the deposit on a transient slot so executeOrder can settle ONLY against the filler's freshly-deposited ETH — never against donated, stranded, or in-flight escrow balance. Plain transfers (no executeOrder follow-up) just sit in balance and can be returned by recovery flows; they cannot be drained via fillOrder.

receive() external payable;

Router

Git Source

Inherits: EIP712

Title: Router

Author: @msakiart

Thin entrypoint for makers (swap), fillers (fillOrder), and makers cancelling orders (cancelOrder). All three actions go through IPoolManager.unlock so the hook can operate on PM debts. Gasless variants (swapWithSig, cancelWithSig) take the maker's EIP-712 signature so a relayer can submit. Signed creates pull input through Permit2 with the order as witness, so the wallet shows the full order (tokens, amounts, pool) in one readable message.

swap

Maker submits a new async order. userData must encode AsyncSwap.UserParams with executor == address(this) so the router is authorized to fill later. userData.amountOutMin MUST equal order.amountOutMin — the router enforces this so the limit price the maker signs in order is exactly what beforeSwap stores via hookData. The hook auto-assigns a salt on create and emits it in AsyncOrderCreated. Submitters can pass order.salt = bytes32(0) on initial submission; the field is only read on cancel / updatePrice / fill paths (where the maker supplies the salt fetched from the indexer or event log). Native input (currency0 = address(0) and zeroForOne = true, OR currency1 = address(0) and zeroForOne = false) requires msg.value == order.amountIn — the router holds the ETH and settles it to PM during unlock. For ERC20 input the maker must approve the router for amountIn of the input token.

function swap(AsyncOrder calldata order, bytes memory userData) external payable;

fillOrder

Filler completes an open order, paying the maker's net minimum plus the protocol fee. For ERC20 output, approve the router for that gross amount. For native output, msg.value must equal the live net price plus the protocol fee; a stale or excessive deposit reverts rather than stranding the difference. Native output is currency1 for zeroForOne, otherwise currency0. maxPrice caps total output paid, including the fee — it protects fillers from a maker who front-runs them with updatePrice to bump the order's stored price. Pass type(uint256).max to disable the check.

function fillOrder(AsyncOrder calldata order, uint256 maxPrice, bytes calldata) external payable;

swapWithSig

Relayer submits a maker's signed order. The maker signs a Permit2 PermitWitnessTransferFrom for amountIn of the input token with spender = Router and the AsyncOrder witness (see OrderSignatures), so one signature both approves the transfer and commits to the order. Input then lands in the hook escrow exactly as in swap. Requires a prior Permit2 approval of the input token; native input is not supported (use swap).

function swapWithSig(AsyncOrder calldata order, PermitData calldata permit, ExecutorGrant calldata grant) external;
